# ADR-001: 최종 홀드아웃 검증 도입

## 상태
결정됨 (2026-04-07)

## 맥락
Walk-Forward 그리드 서치만으로는 간접 과적합을 방지할 수 없었다. WF 검증 결과를 보고 스코어링 함수나 파라미터 공간을 조정하는 순간, 검증 데이터도 사실상 학습에 사용된 셈이 된다.

## 결정
데이터 끝 2개월(HOLDOUT_DAYS=60)을 WF 그리드서치에서 완전히 제외하고, 최종 선택된 파라미터를 1회만 평가하는 홀드아웃 세트로 사용한다.

## 이유
- 방법 A(홀드아웃): 코드 변경 최소, 과적합 여부 즉시 판단 가능
- 방법 B(파라미터 안정성 필터): 유효하지만 홀드아웃 없이는 최종 검증 불가
- 방법 C(그리드 축소): 조합 수를 줄여도 근본적으로 과적합 검증이 안 됨
- A를 먼저 적용하고 B는 추후 추가하기로 결정

## 결과
- WF에 사용되는 데이터가 2개월 줄어 폴드 수가 9→8개로 감소
- 최종 요약에 "WF vs 홀드아웃 비교표"가 추가되어 과적합 판정 가능
- 홀드아웃에서 마이너스인 전략은 실전 투입 전 재검토 필요
